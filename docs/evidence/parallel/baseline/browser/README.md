# Merged-baseline browser QA

Local, real API on port 8104 with a separately started Next development server on 3104 and headless Chromium CDP on 9324; no AWS writes or model calls. The browser scripts were copied to `/tmp` and adjusted for the isolated ports. No tracked source or dependencies were changed by this QA (Next added its usual generated include paths to `web/tsconfig.json`; the integrator removes those after the server stops).

The six-route smoke covered Markets, Risk Intelligence, Sources, Portfolio, Profiles and World Explorer, with no JavaScript exceptions. The new navigation includes Markets and Risk. The World Explorer rendered a globe canvas, Japanese airport references and source caveat, and Canadian ECCC 2024 facilities with the reporting-company/no-ownership caveat. `globe-interactions.json` records a configured 390 px viewport with `innerWidth=390` and `scrollWidth=390`. `globe-and-layers.png` captures the globe stage.

A separate real-HTTP browser interaction created a JPY account, rendered its pinned CAD conversion receipt, aggregated the fictional accounts, and checked a complete target allocation with before/after metrics and policy checks. Screenshots are `browser-account-receipt.png` and `browser-target-allocation.png`; there were no JavaScript exceptions. The first harness measured a widened 558 px viewport despite requesting 390 px, so its reported equality of viewport and scroll is not sufficient as a 390 px mobile pass.

**Decision Desk mobile acceptance failed.** The configured viewport was 390 px before navigation. Decision Desk expanded to `screen.width=390`, `innerWidth=482`, `document.scrollWidth=482`. The reproducible cause was the hidden `Instant rule check` `.info-bubble` at x=170.03…482.03, width 312, with `visibility:hidden; opacity:0` and start alignment. The target/policy tables were correctly contained in 308 px overflow-scroll wrappers. Temporarily hiding only `.info-bubble` in the browser reduced inner/document width to 390. Diagnostic data is in `../mobile/mobile-overflow-diagnostics.json`; these are **pre-fix** observations, not a passing mobile test. The root integrator is applying and checking a focused fix.
