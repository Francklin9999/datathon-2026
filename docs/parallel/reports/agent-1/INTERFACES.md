# Agent 1 interfaces for integration

Baseline: `2604b9689e9f992b4e9e46c4a06ea89ec57ac155`; branch `codex/agent-1-investor-quant`. Contract version remains 1.4.0. Additions below are local branch interfaces; reconcile shared types, regenerate schema/TypeScript after integration, and test against the integrated implementations. Core requests and response bodies remain session-owned; all `/v1` calls below require `X-Aplomb-Session` unless the baseline specifies otherwise. Do not use example data as real observations.

## Profile and account APIs

- `ProfileService.get(session_id, profile_id)` returns the ordinary profile engine's session-owned profile, version, rules, active traded portfolio and account data. Seeds do not switch the engine by name. `investorContext` adds capacity/origin, investor type/language, dated horizons and goals, explicit requirements, targets and rebalancing preferences. New origin metadata is optional for backward compatibility and cannot justify inventing missing legacy provenance. Regulatory origin is rejected until a verified implementation exists.
- `POST /v1/profiles/{profileId}/custom-rules`: `{"version": 3, "dimension": "position", "key": "SPY", "operation": "cap", "threshold": 20}`. Enumerated dimensions are position, direct sector, asset class, listing-country proxy, quote-currency proxy and catalog theme; operations are cap/floor. The returned `Profile` advances its optimistic version. This is not a free-form interpreter.
- `POST /v1/profiles/{profileId}/accounts/{accountId}/refresh`: `{"version": 3, "asOf": "2026-11-12"}`. Omitting `asOf` selects current pinned data; supplying it explicitly applies historical availability even on the snapshot observation date. A new FX receipt is saved only after validation; prior receipts are in `valuationHistory`. A failed rate or stale version leaves the profile unchanged. This is modeled capital, not a currency trade.
- `POST /v1/profiles/{profileId}/accounts/{accountId}/transfer`: `{"version": 3, "destinationAccountId": "acct_012345abcdef", "amountReporting": 100}`. Moves proportional traded holdings at their reporting-currency values; aggregate capital is conserved, both accounts remain positive, and current affected FX receipts are retired to history. No fees, tax, execution or private-asset transfer is implied.
- `POST /v1/profiles/{profileId}/accounts/{accountId}/private-assets`: `{"version": 3, "name": "Example appraisal", "assetType": "art", "valuationDate": "2026-11-01", "origin": "user", "sourceDescription": "Owner estimate", "nativeCurrency": "EUR", "nativeValue": 1000, "liquidityNotes": "Sale time unknown"}`. Supplying an existing `assetId` appends an appraisal history. `GET /v1/profiles/{profileId}/account-valuations` returns separate modeled-traded, private and combined values. Private appraisals are additional and excluded from traded-weight, return and risk engines; do not count them twice or treat an appraisal as a sourced market quote.
- `GET /v1/profiles/{profileId}/allocation-targets` compares stored target percentages to supported measurements, returning drift, threshold, state, origin, local `factId` references, ledger and limitations. Measurements are traded-portfolio only, with listing and quotation proxies. No orders are placed.
- `POST /v1/profiles/{profileId}/requirements-scenario`: `{"asOf":"2027-01-01", "through":"2027-12-31", "liquidCapital":2000, "annualReturnPct":0, "cashflows":[]}`. Evaluates the profile's explicit dated requirements; spending/liabilities withdraw, liquidity reserves set a minimum. Returns missing-input, modeled shortfall or modeled funded state and event trace. Empty explicit cashflows assume no other inflows/outflows. Input capital is liquid capital, not inferred from total wealth; return is assumed, not forecast.

## Agent 1 to Agent 2: calculations and candidates

- `CheckService.check(session_id, CheckRequest)` preserves the baseline incremental purchase semantics. `CheckRequest.knowledgeMode` is additive: omission preserves current-snapshot semantics when `asOf == snapshot.dataAsOf`; `"historical"` requests actual point-in-time availability even on equality; `"current"` is rejected for a date earlier than the snapshot. `/rebalance/check` remains the read-only complete final-target, constant-capital comparison and returns local facts. It does not run or claim an agent review.
- `quant.candidates.strategic_brief(profile, snapshot, now, limit=3)` and `GET /v1/profiles/{profileId}/strategic-candidates` produce up to three ranked policy/goal findings. Each candidate has `candidateId`, `kind`, `severity`, `label`, `factIds`, `evidenceIds`, `affectedHoldings`, `investigation`, `navigationTarget`, `missingInputs`, and `claimIds`. `facts` is a local ledger for that response. **`claimIds` are empty:** Agent 2 creates genuine claims and must remap all local fact IDs and dependencies into the canonical run ledger before registration/auditing. Do not copy `F-001` into another ledger unchanged. Candidate findings are not LLM output, a signed review, or investment advice.
- `POST /v1/decision/target-funding`: `{"totalValue":100, "before":{"A":0.6,"B":0.4}, "target":{"A":0.25,"C":0.75}, "externalFlow":20}`. Weights are fractions, external flow is in reporting currency; positive is deposit, negative withdrawal. Returns position-value changes, sales, purchases and resulting capital. Sales + deposits equal purchases + withdrawals. This endpoint is an explicit-input arithmetic port and does not retrieve a profile; caller owns session/profile/version binding. Reject impossible totals/negative weights. Existing target policy/risk comparison is constant-capital and must not be mislabeled as an after-flow value calculation.
- `POST /v1/risk/scenario`: `{"asOf":"2024-01-01", "weights":{"A":0.6,"B":0.4}, "shock":{"kind":"interest_rate","key":"CAD","change":100,"assumption":"parallel rise"}, "sensitivities":{"A":{"value":-5,"source":"user assumption","asOf":"2024-01-01"}}}`. Interest/spread shock units are basis points; currency/commodity/factor changes are fractions; sensitivity is signed. Output `impactFraction` is null when any nonzero position lacks sensitivity and `knownImpactFraction` is only a partial sum. Inputs are user supplied and unverified, first-order, without convexity/interactions/costs. Currency direction is reporting currency per unit of foreign currency.
- `POST /v1/risk/factor-fit`: `{"names":["market"], "returns":[{"start":"2024-01-01","end":"2024-01-02","value":0.01}], "factors":[{"start":"2024-01-01","end":"2024-01-02","riskFree":0.0001,"factors":{"market":0.005},"source":"user-provided capture"}]}` illustrates the schema only; the model requires at least 30 exactly aligned periods and a non-singular sample. Response includes per-period alpha, betas, residual deviation, R², sample dates, excluded counts and source IDs. The caller must provide valid dates, consistent currency, permitted data and suitable sample; no source fetch or guarantee is implied.

## Agent 2 to Agent 1: exact fund holdings

`POST /v1/risk/fund-look-through` and `quant.exposures.look_through` accept exact checksummed ISINs, long-only portfolio fractions, attributed dated fund snapshots and a historical/current visibility mode. Each snapshot includes `fundIsin`, `holdingsDate`, an Agent 2 `Evidence` object (`source_id`, HTTPS `url`, content SHA-256, availability/retrieval timestamps, licence), and `{isin, weight}` constituent fractions. Response separates direct and indirect exposures, unresolved fund weight, snapshot dates/source IDs and disclosed pairwise overlap. Partial disclosures are not rescaled; overlap is a lower bound; no nested-fund, derivative or issuer-group relationship is inferred. The existing reference fixture is synthetic. Actual issuer capture, security IDs/crosswalk, retrieval and terms are Agent 2 responsibilities; end-to-end production acceptance remains pending.

## Financial sources

`GET /v1/risk/source-inputs?asOf=YYYY-MM-DD` returns bounded capture-gated context: sources with status, observed value, provider URL, capture time, SHA, rights and limitations. Captured NY Fed SOFR is an overnight rate, Treasury par yields are not zero-coupon rates, Treasury debt is a fiscal aggregate, CFTC COT is positioning for an explicitly named contract, and CFTC swaps is aggregate gross notional. None establishes holding sensitivity or a live option chain. Retrieval bounds historical availability; original provider vintages are not proved. Fama–French is unavailable without a validated capture. STLFSI4 is captured but intentionally awaits Agent 2's FRED adapter. Source rights and remaining adapters are itemized in `SOURCES.csv`; local captured files are not a replacement for integration-owned snapshot publication.

## Latest API-first pass and source-scope change

The user subsequently requested APIs over new test cases, exclusion of paid plans and deferral of login/API-key feeds. Added these session-protected routes without a contract-version bump:

- `GET /v1/risk/providers`: six anonymous transport/parser connectors and their honest readiness; CME excluded, OANDA/FRED set aside.
- `POST /v1/risk/providers/{providerId}/capture`: `{asOf:"YYYY-MM-DD",symbol?:"SPY",sheet?:"",limit?:100}`. `limit` is 1–200. Only server-confirmed permitted anonymous sources can be requested. No user URL or credentials are accepted. Returns normalized source records, unit/limitations, source URL/hash/retrieval, immutable capture ID and query/version.
- `GET /v1/risk/providers/{providerId}/captures/{captureId}`: session-owned, raw checksum rechecked; optional `X-Aplomb-Known-Date` withholds a later capture. Raw bytes and credentials are not returned.

The router receives the existing application store and session dependency from `api/app.py`; it uses existing `cache` records and storage spilling. Provider contracts are narrow additive runtime models in `financial_provider_api.py` and TypeScript client validation; they do not independently change the common 1.4.0 contract version. Details: PROVIDERS.md. FRED raw data was removed before commit; old text above describing it as an installed capture is superseded.
