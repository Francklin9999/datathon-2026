# Agent workflows handoff

## Implemented

- `POST /v1/runs` accepts `kind: "rebalance"` with `profileId`, `profileVersion`, `lang`, `positions` and optional `window`; it pins the exact session-owned profile, snapshot manifest, and the result of the existing `CheckServiceImpl.rebalance` computation at preparation. Weight validation, omitted positions, constant capital, policy rules, costs and restrictions are unchanged. `GET /v1/runs/{id}` returns a new `rebalance` result with the comparison and signed brief. Run ownership, request idempotency and checkpoints use the existing coordinator.
- The quant step copies the deterministic local facts to the actual run ledger in dependency order and rewrites fact references throughout the comparison. The target policy checks then pass to the existing writer, independent auditor, guardrail/signing and frozen run ledger. Tests include a deliberately populated run ledger to exercise ID collisions, and confirm every returned policy reference and dependency resolves in the run. Historical data remains pinned to the comparison snapshot; no live research claims are introduced into it without registered evidence.
- Agents & System now offers a keyboard-accessible final target input and reviewed analysis, timeline, snapshots, policy checks and signed brief. On model failure the page points to the independent deterministic target check in Decision Desk. `TargetReview` can also be embedded by Agent 1's Decision Desk. Evidence lookup recognizes the added result type.
- Failed tool traces now use a fixed error rather than raw provider exception text, and server run-failure logs no longer contain raw exceptions. Optional research model/budget failures disclose the gap and allow deterministic controls to continue.
- Existing Strands Bedrock runtime uses real SDK `BedrockModel` with one charged schema repair or transient transport retry, one model turn per call and disabled SDK retries; AgentCore is not required. Existing tests mock the SDK, not live AWS. Runtime remains bounded by call/time budgets and checkpoint/lease ownership.
- The existing horizon-aware portfolio brief ranks at most three code-derived findings using plan checks, fixed-income presence and nearest user objective; it includes evidence IDs, limitations, investigation links, generic profile context and explicit heuristics. Existing event workflow relies on code-matched source observations and explicitly separates a price move from causation.

## Typed cross-agent ports

`AgentServices.candidate_provider` can provide `CandidateFinding(topic, priority, fact_ids)`; each reference must already be a verified fact in the current run ledger. It can prioritize the existing risk/concentration/plan/fixed-income cards, not inject prose or bypass policy checks. The built-in priorities remain the fallback if the port is absent or rejects its inputs. This is a limited adapter; Agent 1's full arbitrary candidate schema and objective-specific prioritization are not yet integrated.

`AgentServices.event_relationship_provider` receives the event, profile, cutoff and run ledger, and may return bounded `EventRelationship` objects. The adapter requires direct `EVENT_REFERENCES_ENTITY` and `SECURITY_ISSUED_BY` edges sharing an exact entity, relationship availability/retrieval no later than cutoff, and same-run verified evidence with matching source URLs. Leads always retain `impact: not_established`; a listing-to-session-holding bridge is still needed before claiming portfolio exposure. The source provider must register source documents and evidence with the ledger, and future integration must verify source body/hash and the security/listing mapping. Invalid or unavailable adapters produce no asserted relationship and disclose a limitation. Synthetic bridge tests establish date, identity and foreign-reference rejection; they do not establish that real event-to-issuer relationships exist.

Additional security: `ToolRegistry.execute` now redacts exception details before they can appear in tool traces or researcher observations; a test proves a deliberately secret-bearing provider exception is not returned. Existing tests exercise prompt injection as untrusted document text, role allowlisting, budget limits, cancellation, worker checkpoint resume and same-run isolation. None of these tests guarantee immunity to every prompt injection.

## Independent source interpretation review

`Ledger.source_review_context(evidence_id)` retrieves bounded excerpts around up to three matches of the verified quote in the immutable same-run captured document, with the SHA-256 of the complete original UTF-8 source and character offsets. The source hash is included in the evidence verification check, binding it into the signed ledger digest. The auditor receives context only for evidence actually cited by a sentence; a missing or foreign document fails closed. The prompt explicitly treats all source excerpts and investor text as untrusted data, and instructs the reviewer to report A09 for unsupported, ambiguous or contradicted interpretations. A bound of twelve cited evidence items and three excerpts per item limits model context. This still relies on the model to interpret language and can miss subtle errors; it is not a universal truth guarantee.

`backend/tests/agents/test_source_review_context.py` uses a synthetic source that denies a merger, includes hostile embedded instructions and is paired with a false claim of a completed merger. A synthetic independent reviewer sees the exact original excerpt/hash, reports A09, and the writer repairs it before another review. Foreign references are rejected. An additional synthetic investor-text injection test confirms that proposed portfolio and rules are dropped by profile-draft code controls. Full focused `backend/tests/ledger`, research tests, source-review and research-boundary integration tests passed (212 tests). Tests use scripted model responses and do not establish live model reliability.
