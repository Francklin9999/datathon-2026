# Historical work handoff

## Implemented

- `timemachine/service.py` and shared `api/domain.py`: a reveal is saved as a session-owned, immutable, create-if-absent record in the existing store, with parent run SHA-256, parent run ID, data version, creation time and complete result (scenario observations and facts). Repeating the same session/run/until returns the original result; a mismatched parent or snapshot is refused. The parent run and its ledger are never changed. `ReplayServiceImpl(..., store=...)` supports tests that need no persistent store; the default runtime supplies the existing repository store. No API/contract change.
- `timemachine/vintages.py`: parser for rights-cleared ALFRED-style real-time periods; rejects overlapping vintages, invalid dates/values and secret-bearing URLs, preserves distinct observation date, real-time interval, retrieval timestamp and dataset version, and chooses the vintage valid at the requested end-of-day UTC cutoff. Publication time is unknown rather than invented. Synthetic tests only; no fetch, retention or AI-tool wiring.
- `TimeMachinePage.tsx`: accurate explanation that rows can be withheld because availability is unknown or late even when observations predate cutoff. Existing UI shows model-knowledge, hindsight and adjusted-price caveats.
- `test_global_fx.py`: same snapshot-date historical gate explicitly withholds the later BoC capture, while current mode sees it.

## Historical source access and open work

FRED/ALFRED terms published at https://fred.stlouisfed.org/legal/ state that FRED content may not be used in connection with development or training of AI systems and restrict API caching/storage and redistribution; the terms also cover ALFRED and third-party rights. API docs https://fred.stlouisfed.org/docs/api/fred/series_observations.html require an API key, and historical intervals have date-level rather than precise release timestamps. Permissions and provider-specific rights for the intended product and model use are required before actual ingestion, storage, redistribution, or use in AI workflows. Offline exploratory graph requests confirmed that `vintage_date` returns the requested vintage in the CSV header whereas `revision_date` was ignored; no response body is retained. A parser alone is not an actual source integration. Point-in-time security, fundamental, news and ownership sources remain unimplemented/need source-specific rights and data. No historical claim is based on synthetic data.

## Additional history and checkpoint verification

- `timemachine/records.py`: narrow immutable versioned point-in-time record selector for security, fundamental, news, ownership and filings. It validates content hashes, source metadata and distinct publication/availability/capture, withholds unknown or future availability and selects revisions by availability. This is not wired to a provider or UI; tests use synthetic records, not evidence of live coverage.
- Shared `ledger/core.py`: new checkpoints add a canonical context/document/bundle checksum; restore rejects modified checkpoint, mismatched run/cutoff and verified quotations that no longer match their original same-run documents. Legacy checkpoints without the new digest remain readable only if their existing fact hash and verified documents pass checks; the unkeyed digest detects corruption but does not authenticate a malicious writer who can rewrite both state and hash. Fact writes after a restore continue to use immutable sequential IDs. `backend/tests/ledger/test_ledger.py` adds corruption, session/run and legacy-document coverage. Crash/recovery behavior is also covered by existing repository/persistence tests.
