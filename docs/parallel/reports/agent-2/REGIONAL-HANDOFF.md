# Regional market research handoff

`backend/aplomb/research/regional.py`, `GET /v1/intelligence/regional`, and `web/src/features/markets/RegionalResearch.tsx` provide explicit routing for Japan and South Korea. The Markets page includes the component. Requests require the session header, a region, an exact provider identifier, and an interval no longer than 366 days; unsupported regions never fall back to a US source.

Japan uses J-Quants v2 daily equity OHLC (`https://jpx-jquants.com/en/spec/eq-bars-daily`) with a five-character TSE issue code. Unadjusted and adjusted closes are returned separately in JPY. No ISIN or issuer relationship is inferred. The provider says adjusted prices are retroactively revised, exclude dividends and that original item availability timestamps and correction vintages are unavailable; no historical reconstruction is asserted. Coverage is limited to TSE, not all Japanese exchanges. A response with a pagination key is explicitly partial, rather than silently called complete. Enable only after authorization with `APLOMB_JQUANTS_KEY` and `APLOMB_JQUANTS_RIGHTS_CONFIRMED=true`. The flag records operator configuration, not an independently verified licence; review redistribution, storage and allowed deployment terms for the actual account first.

South Korea uses official OpenDART company and filing list endpoints, requiring the eight-digit DART corporate code and `APLOMB_OPENDART_KEY` plus `APLOMB_OPENDART_RIGHTS_CONFIRMED=true`. Official documentation: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002 and https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001 . The company endpoint need not echo its requested code, while each returned filing must match the exact code. A provider-reported stock code is not an independently verified listed-security crosswalk. Filings carry receipt dates, not invented publication timestamps, and the UI labels first-page partial results. The API key is transmitted only to the official fixed endpoint; the saved source URL excludes query credentials. No credentials are returned or written, and a response echoing the key is rejected. The source terms and permitted storage/redistribution must be reviewed for the intended use.

Configured, successful responses are saved using the existing store under a session-hashed partition with immutable content-addressed raw and normalized captures. The dataset version derives from provider, exact query dimensions and source SHA-256 hashes; an identical capture reuses its original retrieval timestamp. Availability is set conservatively to capture time, not inferred from observation/filing date, and is not wired into agent historical tools. The API returns provider failure as sanitized unavailable errors. Source pagination is bounded; no retry loops, bulk scraping or reverse ticker lookup is performed. Missing key or operator rights configuration returns an honest unavailable state.

`.venv/bin/pytest backend/tests/unit/test_regional_research.py -q` passed seven tests: synthetic provider success, identity mismatch, region failure, time bounds, unavailable defaults, session isolation, immutable capture, secret exclusion and HTTP success/unavailable. `npm run typecheck --workspace web` passed. Fixture examples are synthetic and do not establish live provider coverage or rights. No actual licensed account, live response, company statements, ownership or news is claimed. J-Quants statements and OpenDART financial/ownership endpoints remain unimplemented; real credentialed provider validation and coverage are still required. Add a typed generated contract/schema for this new response during integration, and conduct local UI/browser verification when the combined branch is stable.
