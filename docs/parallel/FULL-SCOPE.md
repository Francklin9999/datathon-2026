## Universal product principles

Aplomb connects investor → world → assets → risk → challenged decision → evidence → historical learning. It is one investigation platform, not disconnected dashboards. Support starting from a portfolio, investment idea, security, country, geopolitical/macro event, article or historical date. Global architecture and UI are separate from independently maturing geographic, securities, disclosure, macro, event, currency and account coverage. Be explicit about each boundary.

Profiles are unlimited/extensible in principle, with Robert, Amira and Mateo as ordinary seeded configurations. Policies/calculations must never branch on those names. Model arbitrary investor types (retail, growth/balanced/retirement/ESG/income/crypto, institutions/family offices/endowments/pensions/wealth managers/advisors/custom), residence/tax jurisdiction where supported, ISO reporting currency, language, objectives, multiple deadlines/horizons, risk tolerance/capacity, liquidity, portfolio value/holdings, asset permissions/restrictions, position/sector/country/currency/crypto/leverage limits, drawdown/volatility budgets, ESG/exclusions/themes, target allocations/rebalancing and validated custom conditions. Every policy/input retains its origin; no system default is regulation. Multiple accounts and aggregate views must include explicit illiquid/private valuation limits and sourced FX.

Finance is deterministic. Specify portfolio return weights, covariance/variance, FX direction/composition, price/corporate-action convention, calendar alignment, rebalancing, missing observations, samples and revisions. All material numerical claims are reproducible. No arbitrary user Python/SQL. Never invent ETF constituents, issuer relationships, licensed access, precise event impacts or unavailable data. Modern LLM prior knowledge remains separate from historical predictive calibration.

Do not automate restricted NewsAPI plans, public Nominatim bulk use, Google Trends alpha, licensing-dependent real-time exchange/aviation/AIS or commercial APIs under unsuitable terms. An unavailable commercial feed is an external dependency; it is not an excuse to leave other source modules unimplemented.

Ingestion is shared provider adapters → validation → entity resolution → timestamps → quality → versioned storage → evidence/claims → tools → financial/world services → UI. Keep original provider/URL/record, dates/version/licence/quality, geography role, exact entity IDs, permitted payload reference, content hash and limits. Graph relationships include SECURITY_ISSUED_BY, ENTITY_PARENT_OF, FACILITY_OPERATED_BY (only with proof), ENTITY_HEADQUARTERED_IN, COMPANY_REPORTS_REVENUE_IN, FACILITY_LOCATED_IN, COMPANY_SUPPLIES_TO, SECURITY_HELD_BY_PORTFOLIO, EVENT_OCCURRED_AT, EVENT_REFERENCES_ENTITY and CLAIM_SUPPORTED_BY_SOURCE. Date/evidence/class each relationship. Exact codes/IDs and source records precede matching. Financial relevance progresses from no documented relationship to candidate, documented nonfinancial link, measurable exposure and modeled impact; do not collapse these into a fake impact score.

Global normalization uses standard country/currency IDs and canonical timestamps, localized rendering and initial English/French architecture. Backend must bound timeout/retries/pagination/rate limits/data validation/caches/dedup/idempotency/errors/model budgets/session scope. Frontend must lazy-load and limit spatial rendering, cache static data, expose loading/errors, work responsively and accessibly in dark/light themes. Credentials stay private; external documents/text cannot instruct agents; tool rights remain limited; verified deterministic results survive model/provider failure with honest status.
