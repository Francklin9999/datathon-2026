# World Explorer to Decision Desk handoff

The event panel links each code-matched holding to Decision Desk. The link carries the event ID, ticker, profile ID, and, when opened from a completed event brief, its run ID. Decision Desk links back to the event's original source list and to the brief's evidence. A matching ticker fills the hypothetical move form; the user still selects the amount and funding. Relevance does not establish financial impact or causation.

The link is a convenience, not a signed event-to-decision claim. The backend does **not** independently validate that the event, ticker, or referenced source run are related or that the source run exists. Identifiers are untrusted context. Event-brief evidence remains accessible only under the existing session controls. No source URL is accepted from the handoff; internal event and run URLs are constructed from strictly validated IDs.

To restore context when a decision run URL is reopened, the client appends a marked JSON record to the existing `originalText` field. It accepts bounded, grammar-checked IDs and ticker, and treats the marker as untrusted context, not a request to trade or a verified assertion. A decision run pins its persona; the client only restores saved context for that persona. Selecting another persona remounts the form. The backend retains `originalText` and the client restores it; this is not an independent audit of the relationship. A future typed, validated contract should replace the marker for stronger lineage.

Checks on the integrated tree: `npm run typecheck` passed; `npx tsx --test web/tests/t15-logic.test.ts` passed (21 tests, including context round-trip and invalid IDs). Headless Chrome loaded local `/world-explorer/` at a 390-pixel viewport and returned HTML; that does not establish interactive behavior, visual quality, cross-page correctness, or AWS availability. The complete browser journey and other requested viewports remain unverified. World Explorer and event briefs remain disabled in the deployed API as observed in the release audit; this local handoff does not change feature flags or deploy anything.

A later Playwright/Chrome headless pass used the already-running local Next server on port 3000 and confirmed requests to the local API on port 8000 (`snap-20261113-starter`). Nine routes loaded at each of 390, 768, 1024, 1280 and 1440 pixels: 45 HTTP 200 responses, no uncaught page exceptions and no document-level horizontal overflow at the time sampled. Screenshots and machine-readable results are in `/tmp/aplomb-browser-qa/`; these are local, non-release artifacts. The check was not a full accessibility audit or a verification of all browser console messages.

At 1440 pixels, opening an official Federal Reserve event, selecting the AGG holding link, and arriving at Decision Desk populated AGG and displayed the event context with a link back to its sources. This verifies the navigation handoff only. It did not execute a decision run or independently validate the event/holding relationship. A separate server on 3100 could not start because Next.js detected the existing dev server; it was left intact.
