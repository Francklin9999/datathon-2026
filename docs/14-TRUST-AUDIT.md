# Quantitative and temporal audit

Inspected the numerical primitives, FX conversion, funding, temporal reader, replay and ledger audit. Portfolio returns are simple returns weighted daily; volatility uses sample standard deviation times sqrt(252); drawdown is a positive peak-to-trough magnitude. USD-to-CAD multiplies USD prices by USD/CAD, while CAD-to-USD divides. The resulting portfolio is a constant-weight reconstruction, not account performance. Existing synthetic and starter controls test these paths; these checks do not establish that source history was unrevised.

The historical gate filters on the mode-specific availability timestamp; replay re-derives derived thresholds at the cutoff and reveal uses a separate ledger. Reveal checks the run session. Historical model knowledge, adjusted-price revisions, retrospective universe selection and unavailable true macro vintages remain disclosed limitations; a client-generated session capability is not authenticated identity.

The auditor validates reference grammar, same-run fact/evidence provenance, numeric literal controls and structured comparisons, and uses a model to review unsupported interpretations. Its coverage is bounded: it is not proof that all qualitative claims are true or hallucinations impossible.

A defensive gap was fixed: `portfolio_returns` previously used `zip`, silently ignoring excess weights or series, and accepted mismatched lengths or non-finite values. It now rejects these inputs, with a numerical regression test. Normal engine-generated aligned series retain the same result.

## Sabotage workflow and comparison verification

The prior 1.0.0 `POST /runs/{runId}/sabotage` contract expected a queued child and `SabotageResult.briefBeforeAudit`. That field is typed as `Brief`, whose audit requires a status, ledger hash and `signedAt`; each sentence also requires a verified/struck/repaired status. It therefore cannot honestly represent an unreviewed writer attempt. The local 1.1.0 implementation now includes the child workflow and an explicitly unsigned attempt. The deployed feature stays disabled until real-model validation.

The coordinated contract revision added a distinct explicitly unsigned draft type (raw sentence templates, writer/model identity and attempted instruction; no audit status or signature), preserve a separately audited `Brief`, and represent refusal/no injected assertion explicitly. The implementation adds session-owned child creation, a fork of the frozen parent ledger, bounded writer and reviewer calls, checkpoints, strict `caught` based on a failed check applied to the designated offending sentence, and UI labeling. Parent immutability, another-session denial and an absent designated sentence have scripted integration tests. Exercise each attack, worker crash/retry and real Bedrock before enabling the flag. These requirements cannot be met honestly by labeling a scripted injection as an actual writer attempt.

The existing auditor now independently compares extracted operators with simple, unnegated directional prose between two cited facts. It catches a true but reversed relation extracted by a reviewer for a false statement. Complex, negated and other qualitative language still relies on the model reviewer and is not proven by this guard. `backend/tests/ledger/test_sabotage_controlled.py` tests numeric fabrication, false comparison, unsupported interpretation (with a scripted finding), and reversed operator extraction. `UV_CACHE_DIR=/tmp/aplomb-uv-cache uv run pytest backend/tests/ledger -q` passed 155 tests, and ruff passed for the changed audit and controlled test. These are controlled tests; no live sabotage or model call is claimed.

A real local Bedrock smoke (not AWS deployment) completed a decision and sabotage child, preserving the parent and rejecting another session. The writer returned no designated attack, so `caught=false`: this is not evidence that an attack was caught. See [sanitized smoke evidence](evidence/release-hardening/current-code-sabotage-bedrock-fixed.json). Scripted tests exercise all modes and worker crashes at writer and auditor boundaries. A sabotage child uses the parent report language to prevent mixed-language reconstruction; deployment flag remains off pending a live end-to-end attempt.

Update (2026-11-15): a live AWS attempt confirmed the limit. In all three modes the real writer declined to write the lie, so nothing was inserted and nothing could be caught. The sabotage child now inserts a labelled false sentence built by code from the parent's verified facts, then runs the unchanged real audit. Code checks catch each mode deterministically: A02 for an invented number, A03 for a reversed comparison, A14 for an unsupported impact claim. `caught` is still computed from the actual struck sentence and failed check.
